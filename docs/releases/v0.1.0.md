# v0.1.0 — Interview Project Release Candidate

## Summary

`v0.1.0` captures the reviewed interview-project baseline for the Compliance Triage Agent. It demonstrates how a TypeScript service can place strict application controls around an unreliable model while keeping people responsible for sensitive compliance decisions.

## Included

- Express API with request correlation, strict input validation, and sanitized error contracts;
- PostgreSQL/Prisma case and immutable analysis persistence with atomic status routing;
- OpenAI, Gemini, and Groq adapters behind a provider-independent interface;
- strict structured-output validation, at most one retry, and fail-closed human-review fallback;
- deterministic review rules for safeguarding, high severity, low confidence, missing information, and model concern;
- one minimized, read-only, allow-listed previous-case metadata tool;
- privacy-aware logs and bounded trace metadata;
- 30-case synthetic golden dataset, evaluation metrics, regression gates, and report comparison;
- 146 offline tests and 10 PostgreSQL integration tests;
- multi-stage non-root Docker runtime, reproducible migrations, deterministic CI, and separate manual live evaluation;
- reviewer-first README and a seven-minute interview demo runbook.

## Release verification

The release-candidate audit reproduced install, Docker startup, migrations, API contracts, tests, build, and database validation from a fresh clone. Known credential signatures were absent across the available Git history, `.env` was never tracked, and npm reported zero vulnerabilities.

The 23 September live Groq evaluation did **not** pass every model gate: 29/30 responses were schema-valid because the provider rejected the adversarial prompt-injection fixture. The application handled that failure safely with no invented analysis and mandatory human review; critical-review recall and review routing remained 100%. See [Phase 16: Release-Candidate QA](../phase-16-release-candidate.md) for the full evidence.

## Boundaries

This tag is not a production deployment, legal advice, a correctness guarantee, or GDPR certification. The API has no authentication/authorization or tenant isolation, fixtures are small and synthetic without expert labels, only one bounded read-only tool exists, and the system cannot take autonomous final action. Production use would require security, legal, data-protection, domain, and operational review.
